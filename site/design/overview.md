# 系统设计总览

MyCo-KB 的设计围绕三个问题展开：

1. **知识怎么放** —— 知识包模型：三类知识根统一为一个可挂载、可索引、可同步的单元；
2. **知识怎么找** —— 跨包检索与组合配置：透明打分 + 显式装配；
3. **知识怎么活** —— 生命周期与知识更新流：四态演进、契约驱动、变更可追踪、影响可分析。

## 分层模型

```text
┌─────────────────────────────────────────────────────────┐
│  Agent 面   tools.js（dsh-tools）   skills/（SKILL.md）   │
├─────────────────────────────────────────────────────────┤
│  交互面     CLI（bin/myco.js）      控制台（client.js）    │
├─────────────────────────────────────────────────────────┤
│  服务面     remote.js（Typert）     index.js（Cordis 插件）│
├─────────────────────────────────────────────────────────┤
│  守护面     daemon.js（watcher + 定时维护 + 云同步）       │
├─────────────────────────────────────────────────────────┤
│  核心面     lib/core/*  —— 纯 Node，零依赖，CLI 与插件共用  │
└─────────────────────────────────────────────────────────┘
```

**核心原则**：`lib/core/*` 是纯 Node 零依赖实现（CLI 与插件共用），上层只做形态适配 —— 这保证 CLI、控制台、agent 工具、daemon 对同一份数据给出完全一致的行为。

## 设计决策速览

| 决策 | 选择 | 理由 |
| --- | --- | --- |
| 知识根类型 | repo / local / cloud 三类 | 覆盖项目仓库、本地库、云端多机 |
| 包清单 | `kb.yaml`（id/scope/version/dependencies） | 声明式、可版本化 |
| 组合 | profile（include 列表 + lockfile） | 装配可复现 |
| 检索打分 | tag×3 / 文件名×2 / 全文×1 | 透明、可解释、零依赖 |
| 存储 | 文件为唯一事实源 + `node:sqlite` 缓存 | 无外部依赖、可重建 |
| 变更源 | git diff（git 化包）+ 内容 hash（本地全局） | 双轨兼容 |
| 传播锚点 | 契约块（callout）+ 强引用 | 明确传播边界，避免链接噪声 |
| 人机边界 | 机器检测、agent 起草、**人确认收口** | 不自动删改、不自动落盘 |
| 插件装载 | 标准 bundle（cordis.patch.yml 自声明） | 兼容插件管理页 |

## 核心循环

```text
挂载 → 索引 → 检索/消费
         ↕ (daemon)
变更检测 → 影响分析 → stale → (webhook) → subagent 起草 → 人确认
```

## 后续方向

- 知识更新流深化：更细的契约粒度与传播策略；
- 多用户协作与共享知识库治理。
