## 0. 目标与定位

- **设计文档语义**：按任务自动匹配 profile / 挂载工具，让 agent 拿到「刚好够用」的知识与工具组合。
- **定位**：P3 可选能力跃迁，建立在 v0.1 **静态 profile** + v0.5 **知识更新流**之上，不改变「文件是唯一事实源」。
- **一句话**：把「**任务 → 知识包子集 → 工具面裁剪**」这段缺失链条补上。

## 1. 现状落差（已深挖核实）

| 现状 | 缺口 |
|---|---|
| `profile.match.{用户,环境,目标}` 字段**声明但从未被消费** | 缺少任务匹配引擎 |
| 工具面 `lib/tools.js` 只注册 4 个**静态**工具（status/find/index/sweep） | 无按任务裁剪/注入 |
| kb.yaml 已有 `whenToUse`（适用场景，如 `MyCo-KB 产品自身的知识库…`） | 从不参与匹配 |
| `data/profiles/dev-local.json` 的 `match` 是纯数据，未驱动选择 | 无自动匹配逻辑 |

## 2. DSH 提供的关键机制（已核验，v0.4 可行）

- `agent.ctx.tools.restrict(filter)`：按 **agent 作用域**做允许/拒绝掩码（实时可见性组合，**非权限边界**）→ 用于「按任务裁剪可见工具」。
- `agent.ctx.tools.register(...)`：只为该 agent 注册本地工具并遮蔽同名全局 → 用于「按任务注入专属工具」（如 scoped search）。
- `agent.ctx.tools.presentAs(mode)` / `ctx.tools.guard(...)`：agent-scoped 呈现/守卫。
- 当前任务/目标的读取：需接 agent 上下文（`tool-goal`/goal 或 agent 启动时注入）→ **运行时验证点**。
- 插件本身用 `ctx.webServer.register` 暴露 HTTP API；`ctx.subagents.start` 可后台调度（v0.5.3 已用）。

> 结论：动态装配在 DSH 里是**真实受支持**的（agent 作用域），不是幻想特性。

## 3. 组件设计

```
lib/core/assemble.js     匹配引擎 + 装配解析（纯 Node，零依赖，CLI/插件共用）
  - matchEngine(taskCtx, packages)   打分排序
  - assemble(taskCtx) -> { profile, packages, scopedIndex, toolMask, lockfile }
lib/core/taskctx.js      任务上下文归一化（目标文本 / 用户 / 环境）
lib/tools.js  扩展
  - 新增 myco_assemble 工具（收 goal 描述，返回装配结果）
  - 工具面装配器：对 agent.ctx 施加 restrict + register
lib/index.js             /myco/api/assemble 路由 + agent 上下文钩子
lib/client.js            控制台「当前装配」区（显示的包子集 + 可回退默认）
```

## 4. 装配流程（时序）

```
agent 收到任务
 → 取 taskCtx（目标文本、用户、环境）
 → matchEngine 打分 ⇒ 排序后的知识包子集 + profile
 → 施加 agent.ctx.tools.restrict(mask) + register(scoped tool)
 → （可选）写 lockfile 快照
 → 控制台展示「当前装配」，可一键回退默认
```

## 5. 匹配打分（两层，具体算法）

**第一层：profile 精确匹配**（沿用现有 `match.{用户,环境,目标}`）
- taskCtx 的用户/环境/目标与 profile.match 逐维匹配，命中即锁定 profile 的 include/exclude 集合。

**第二层：知识字节集软匹配**（在 profile 内再缩到「刚好够用」）
- 每包信号：`whenToUse` 语义描述（①LLM/可选 embedding）> 文档 tags（②倒排索引命中）> 文件名（③）> 全文（④）。
- 打分：`w1*语义 + w2*tag + w3*文件名 + w4*摘要`，取 topN；命中为零时回退默认 profile 全量。
- 产出 `toolMask`：任务不涉及的包对应的工具/标签被裁掉，保留检索/装配基础工具。

## 7. 风险与边界（务必写进交付说明）

- `restrict` 是**可见性组合，非权限边界 / 安全非目标**——**不能当安全控制**放机密内容。
- 任务上下文来源需在真实 DSH 运行时验证（agent start hook / `tool-goal` 可用性）——**本轮唯一待实机核验点**。
- 每任务匹配有延迟 → 做缓存 + 命中即回退默认。
- 需 Node ≥ 23（沿用 v0.5 `node:sqlite` store，`DatabaseSync`）。
- 装配只影响「看到哪些」，不改「文件为唯一事实源」的底层约定。
