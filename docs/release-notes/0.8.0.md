# MyCo-KB v0.8.0

**数据目录工作区化 + 呈现契约修正** —— 让 `myco` 在 DSH 会话工作区内可直接运行（绕开文件沙箱的 `EPERM`），并按 dsh-tools 契约输出工具调用视图。

> 版本：0.8.0（minor）。新增数据目录解析逻辑与部署适配，修正 `presentCall` 呈现契约。

## 核心更新

### 1. 数据目录默认改为工作区相对（`bin/myco.js`）
- 新增 `lib/core/datadir.js`：`dataDir` 优先级 = 显式 `dataDir` > `MYCO_DATA` > 默认。
- CLI 默认 `join(process.cwd(), '.myco')`：在会话工作区内运行 `myco ...` 时，数据落进工作区，**绕开 DSH 文件沙箱对工作区外写入的拦截**。
- 此前默认 `~/.myco` 位于工作区外，沙箱内执行 `myco status / sweep / index / scan / contracts / assemble` 会报 `EPERM: operation not permitted, open '~/.myco/index.json'`（或 `attempt to write a readonly database`）。

```bash
myco status                # 在项目目录内运行 → 数据取 <workspace>/.myco
```

### 2. 插件支持 `dataDir` / `MYCO_DATA` 覆盖（`lib/index.js`）
- `apply()` 改用 `resolveDataDir(config.dataDir)`；宿主插件默认回退 `~/.myco`（宿主 `cwd` 非工作区，避免把数据写进 app bundle）。
- 工作区化部署：`export MYCO_DATA=<workspace>/.myco`，或在 profile `cordis.patch.yml` 用 `@dsh/myco-kb` 的 `config.dataDir` 指定。

### 3. `presentCall` 呈现契约修正（`lib/tools.js`）
- 调用视图补上 `card: 'generic'` 字段（dsh-tools render-intent 要求），`kind`/`detail` 仅在存在时输出；修复缺 `card` 被宿主 `viewFor` 当未知卡型回退的降级。

### 4. `.gitignore`
- 新增 `.myco/`，防止把 `config.json`（含 webhook/遥测）与嵌套 `cloud/*` git 仓库提交进仓库。

## 升级指引

**路径 A：自包含安装器 / 自动更新**

```bash
bash myco-install-0.8.0.sh        # 新装
myco upgrade                        # 已装自动更新（查 GitHub Releases 最新版）
bash myco-install-0.8.0.sh rollback  # 回滚
```

**路径 B：DSH 插件管理在线更新（git 依赖）**

```bash
bash scripts/install-release.sh git v0.8.0
```

重启 DeepSeek Harness 后生效。

> **部署注意**：CLI 默认即取 `<cwd>/.myco`（工作区相对）；要让 DSH 宿主插件也用同一数据目录，请在启动前设置 `MYCO_DATA=<workspace>/.myco`（推荐）或用 `dataDir` 配置。迁移方法见 `CHANGELOG.md` `[0.8.0]` 的部署提示。
